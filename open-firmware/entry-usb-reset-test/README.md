# Continuous RAM document reset experiment

This is a separate offline experiment. The open firmware replacement cannot
print; the accepted healthy entry profile remains separate. Current state is
in `CURRENT_STATUS.md` and the detailed continuation is in
`analysis/open-firmware-model/next-evidence.md`. No device access is performed.

The unchanged base `CONTRACT.md` defines memory/entry ownership. `AMENDMENT.md`
changes this sibling profile to one interrupted old document followed by one
fresh document. `ACCEPTANCE.md`/`independent-literals.py` were independently
frozen before candidate code; `ADDENDUM.md`/`literal-addendum.py` add exact ABI
and natural-stop expectations. `LIBRARY_SELECTION.md` freezes the one selected
GCC helper expected from the separate orchestration before its first build.
The underlying production C and reusable TinyUSB/JBIG components are unchanged.

The RAM provider supplies controller images, cache visibility and physical
settlement facts. A real late-success callback must drain before separately
supplied recovery promises. An original cookie is replayed only as inert
metadata after actual buffer reuse. Full memory/register snapshots and raw
call/access/command evidence must support the independent acceptance gate.

`python3 scripts/validate-hp1020-entry-usb-reset.py --audit-only` builds and
checks the linked bytes without target execution. Execution is admitted only
after its own complete audit and source-bound callback/stack review, with a
frozen independent checker. Run checks sequentially. The full command without
that flag captures two paint cases and publishes only after the separate raw
gate accepts them. Do not upload this ELF or use it to contact a printer.

`SOURCE_ORIGINS.json` records the exact originally integrated drafts. Historical
source revisions and failed/accepted captures belong under
`analysis/boot-handoff/entry-usb-reset/source-snapshots/`; report source seals
determine which revision was actually tested.

Frozen checker/literal comments retain their original draft labels. Current
acceptance is established by the exact report/source seals and `CURRENT_STATUS.md`,
not by rewriting historical comments or relabelling an earlier failed capture.
