# Continuous USB RAM experiment

This separate experiment joins the existing USB and document components under
one owned entry, stack and initialization. Six continuous interpreter/QEMU cases
pass the independent raw-capture gate:42 paired full checkpoints and12 actual
park steps. Actual TinyUSB, class, SETUP/EP0/OUT, publication/acquisition and image
components deliver two documents and64 FF output bytes, then drain the final
original owner and finish once. The complete input/linked audit retains all full
production buffers and fits the original53216-byte code cap. Observed stack use
is880 bytes; the separate7472-byte conservative ceiling applies to this fixed
serialized workload only, not asynchronous execution or all inputs.

The profile supplies a reset and raw configuration, settles its ordinary EP0
status, separately supplies three recovery promises, then feeds two documents
without per-document reset or finish. The final outstanding bulk reservation
settles through an explicitly supplied successful zero-length acquisition before
one service, empty pump and finish. That packet is not an EOF or cancellation.

`CONTRACT.md`, the compiler/manual layout tables and independent input/ownership
literals were frozen before runtime C. The independent gate checks full saved
CPU/RAM, original cookies, API/access traces and debugger commands. Earlier code-
budget/dependency stops and the first six-pair run's gateV4 failure remain failures.
V5 requires explicit original-object/discarded-section proof for five unused
shortcut functions, with retained entries still excluded; it changes no runtime
expectations. Exact historical sources/captures and focused control evidence are
in `analysis/boot-handoff/entry-usb/source-snapshots/`. Original draft comments
in preserved sources describe their authoring state, not current acceptance.

Six raw-input refusals, one library seal check, three GC-proof refusals and one
separate entry-predicate control pass. Eleven synthetic evidence corruptions and
32 isolated interpreter guards also pass; they are not additional lifecycles.
The stronger copied-trace ordering control remains unfinished. See
`CURRENT_STATUS.md` for the current full regression and next-experiment status.
The separate reset/recovery proposal remains a draft.

All controller observations, cache-copy behavior, mapping/settlement and output
consumption are supplied RAM conditions. No USB device, physical firmware
loader, engine or installed printing file is used. This ELF must not be uploaded
to the printer; the open replacement cannot print. The earlier entry-RAM and
component experiments remain separate evidence.
